## Collections cost (performance observation, not a threshold)

`cargo test -p bdl-compiler --test backend_differential collections_cost -- --ignored --nocapture`
runs the generated core (debug build, Apple Silicon host, 10 ticks) over one
input list per operation and prints the step time. Recorded 2026-09-18, after
the moved-local emission (`496f1f2`):

| operation | 2 000 elements | 8 000   | 32 000 | scaling 2 000 → 32 000 (×16 in size)             |
| --------- | -------------- | ------- | ------ | ------------------------------------------------ |
| `map`     | 51 µs          | 191 µs  | 763 µs | ×15 — linear                                     |
| `filter`  | 51 µs          | 161 µs  | 627 µs | ×12 — linear                                     |
| `append`  | 42 µs          | 129 µs  | 605 µs | ×14 — linear                                     |
| `sum`     | 35 µs          | 107 µs  | 407 µs | ×12 — linear                                     |
| `length`  | 0.6 µs         | 3.3 µs  | 6.1 µs | the input's bridge copy; `length` itself is O(1) |
| `zip`     | 4.3 ms         | 41.9 ms | —      | ×10 for ×4 — quadratic (ISS-0013)                |

Before the emission change every fold cloned its accumulator per element (the
clone-count test `a_cloned_accumulator_per_element_is_quadratic` keeps that
number visible). These are observations of one machine and build; the structural
guarantees — no clone of a moved accumulator, no state copy per tick, borrowed
`length`/`head`/`take`/`==` — are what the tests hold to
(docs/architecture/codegen-rust.md §Cost discipline).

## Determinism rules under test

- `BTreeMap` everywhere in the model; projections are ordered lists.
- No random ids; ids come from the persisted allocator.
- Hardware solving iterates in documented order; codegen output is byte-stable
  for the same design + compiler version (golden files).
- Generated crates are written under `target/bdl-generated/<case>/` and built
  with one shared `CARGO_TARGET_DIR` (`target/bdl-generated/target`) so the
  runtime crates compile once; the tests spawn `cargo`, so they are slower than
  the rest (≈20 s cold) and need no network.
