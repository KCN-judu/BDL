# Studio ↔ bdld protocol

* **Schema**: `crates/bdl-protocol/proto/bdl/v1/bdl.proto` — the single
  source of truth. Rust code is generated at build time (`prost` + `protox`,
  no external `protoc`); Dart code is generated by `just proto` and checked
  in under `apps/studio/lib/protocol/gen/`; CI fails if it drifts.
* **Version**: `PROTOCOL_VERSION` (Rust) / `kClientProtocolVersion` (Dart),
  currently `0.1.0`. Equal `major` ⇒ compatible. The handshake reports both
  and a `compatible` flag; Studio refuses to proceed on a mismatch.
* **Transport** (v0.1): child-process stdio. Frame = 4-byte big-endian length
  + protobuf payload, 64 MiB cap. Stdout is the channel; bdld logs to stderr.
  Transport and protocol are separate: loopback TCP can be added without
  touching messages.

## Envelope

```
ClientMessage { request_id, oneof payload }   →
                                              ←  ServerMessage { Response { request_id, oneof } | Event { oneof } }
```

Exactly one `Response` per request. `Event`s are unsolicited and only sent
after `SubscribeProject`: `ProjectChanged` then `AnalysisReady` for every
committed revision.

## Requests (v0.1)

| Request | Response | Notes |
|---|---|---|
| Handshake | HandshakeResponse | versions, compatibility |
| OpenProject / InitProject | ProjectResponse | |
| SaveProject | ProjectResponse | `dirty` becomes false |
| CloseProject | Ack | |
| GetProject | ProjectResponse | |
| ApplyEdit { base_revision, EditOp } | EditApplied { projection, outcome } | refused with `edit.stale_revision` if the project moved on |
| Undo / Redo | EditApplied | new revision, no outcome |
| SetLayout | Ack | not a revision |
| SubscribeProject | Ack | then `ProjectChanged` events |
| RunAnalysis | AnalysisResponse { ProjectAnalysis } | analysis of the current snapshot, tagged with its revision |
| Shutdown | Ack | |

Planned (ROADMAP): RunSimulation, SetDeploymentTarget,
SetManualResourceConstraint, GenerateRust, Build, Flash, StartTelemetry.

## Errors

`Error { code, message, details_json }`. `code` is stable and
machine-readable (`edit.duplicate_concept_name`, `session.no_project`,
`protocol.invalid_edit`, …); `message` is designer-readable; `details_json`
carries the typed Rust error for the expert view.

## Projection

`ProjectProjection { revision, name, root_path, concepts[], mappings[],
layout, can_undo, can_redo, dirty }` — a read model for rendering, in
deterministic order. `MappingView.state` carries the paper's workspace state
(`declared` / `defined` today; the rest once the checker exists).

## Deltas

v0.1 sends the full projection after every commit. Incremental deltas are a
planned, non-breaking addition (a new `ProjectDelta` event); clients must
keep treating `ProjectChanged.project` as authoritative when present.
