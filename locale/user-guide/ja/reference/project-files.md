# プロジェクトファイル

プロジェクトはプレーンなファイルのフォルダです。Studio がそれらを読み書きします。フォルダをバージョン管理下に置いたり、コピーしたり、差分を取ったりできます。ツール開発者向けの正式な記述は `docs/spec/project-format.md` にあります。

```text
lamp/
├── bdl.toml                 the manifest: name, schema version
├── src/
│   ├── concepts.bdl         the design — any number of .bdl files, any names, read in path order
│   └── main.bdl
├── .bdl/
│   ├── identities.json      the stable identity of every item — owned by the tools
│   └── authoring.json       behavior groups — owned by the tools
└── ui/
    └── layout.json          where things are on the canvas — not part of the design
```

プロジェクトの種類は 1 つです。その設計は `.bdl` ファイル（[構文の基本](../../../../docs/user-guide/textual/syntax-basics.md)）で、Studio はそれをグラフ、テキスト、またはその両方として表示します（[設計・コード・分割](../studio/code-view.md)）。

## 設計に含まれるもの

意味を持つすべて：コンセプト（名前、説明、値の形式）、関係（名前、説明、読み取り、生成、数式、タイミングドメイン、駆動する出力）、タイミングドメイン、物理出力（名前、受け取るもの、ドメイン、必須）、デバイス（名前、種類、出力、固定ピン）、コンポーネント（それぞれ独自の設計とポートを持つ）、インスタンス、バインディング、エクスポート。

すべてのオブジェクトは、決して変わらず再利用もされない安定した数値の同一性を持ちます。**名前はファイルによる綴り**です。項目の名前を変えると、書かれているすべての場所で名前が変わり、それ以外は何も変わりません。同一性は `.bdl/identities.json` にあり、種類と名前で項目に対応づけられるからです。2 つのプロジェクトで同じ名前を持つ 2 つのオブジェクトは、互いに何の関係もありません。

名前はファイルが綴れる名前でなければなりません。文字、数字、アンダースコアで、数字で始まらず、言語の予約語でないもの（`light`、`pwmLight`、`dimByTilt`）。Studio は他の綴りを拒否し、使える綴りを示します（[ソースファイル](../../../../docs/user-guide/troubleshooting/text-project-errors.md)）。

## サイドカーに含まれるもの

`.bdl/identities.json` は各項目がどの同一性を持つかを種類と名前で記録し、新しいものを配る計数器も持ちます。ソースにファイルにない同一性が必要だったときは開いたときに、毎回の保存の後に、そしてエディタでの保存の後には言語サーバーによって書かれます。ソースとともにバージョン管理下に置き、編集しないでください。削除するとすべての項目が新しい同一性を得ます——意味的なものは何も失われませんが、同一性をキーとするキャンバス位置とグループの所属は失われます。

`.bdl/authoring.json` は振る舞いグループを保持します。テキストはそれを表現しません。メンバーがテキストから消えたグループはそれらを失います。

## レイアウトファイルに含まれるもの

コンセプト、関係、出力、インスタンス、振る舞いボックスの位置。折りたたみ状態。キャンバスごとのパンとズーム。このファイルがなくてもプロジェクトは開き、削除しても配置以外は失われません。位置のない項目はプロジェクトを開いたときと項目が作られたときに位置を与えられ——その種類の列で、読み取るもの・生成するものの横に——位置のあるものは動かされません（[キャンバス](../studio/canvas.md)）。

## 保存されないもの

- デプロイページで選んだ**ボード**——セッションの設定。
- **シミュレーション**——入力、周期、トレース。
- **解析**——すべての判定は開いたときに再計算される。
- **リビジョン履歴**——取り消しはセッション単位。
- どこにいたか——ビュー、ページ、開いていたファイル、ソースを開いていたコンポーネント——は Studio がユーザーごとに自分用に記録し、次に開いたときにそこへ戻します。

見たり編集したりできるすべてはプロジェクトにあります。入力したが追加していない数式——まだ検査を通らないものも、空のフィールドも——はそのまま保存され、エディタに戻ってきます。コードビューのまだビルドできないテキストは入力したとおりに保存されます。ディスク上のファイルは入力したものであり、設計は再びビルドできるまで最後にビルドできたバージョンを表示し続けます（[設計・コード・分割](../studio/code-view.md)）。

## 保存

**⌘S** または**保存**は現在の状態全体を書き込みます。変更されたソースファイルは項目単位の編集として——保存は変更した項目だけを変え、テキストの残り、コメント、空行、並び順はそのままにします。まだビルドできないファイルは入力どおりに書かれます——次にサイドカー（同一性、グループ、未完成の数式、ビルドできないファイルの最後の正しいテキスト）、レイアウト、マニフェストを、それぞれ一時ファイルとアトミックな名前変更を通して書くので、中断された保存が書きかけのプロジェクトを残すことはありません。保存には数式が検査を通ることもファイルがビルドできることも必要ありません。ステータス行の _保存済み_ はそれらのファイルすべてが書かれたことを意味し、それまでプロジェクトは _編集済み_ です。キャンバスで作った新しい項目は `src/main.bdl` の末尾（`main.bdl` がなければパス順で最初のファイルの末尾）、または属するコンポーネント本体の末尾に置かれます。より新しいファイルバージョンは誤読されず拒否されます。

保存は、読み込んでからソースファイルがディスク上で変更されていないことを確認します。変更されていれば Studio は拒否し、再読み込みか上書きを提案します（[プロジェクトをテキストで書く](../../../../docs/user-guide/workflows/authoring-as-text.md)）。

## 古いプロジェクト

以前のバージョンの Studio が保存したプロジェクトは設計を JSON ファイル（`design/project.bdl.json` または `design/system.bdl.json`）に保持し、`bdl.toml` でそう述べていました。それを開くと——Studio で、コマンドラインから、または言語サーバーで——その場で一度だけ変換されます：

- 設計は `src/main.bdl` に書かれる。
- すべての項目は同一性を保つので、位置、色、グループの所属は変わらない。
- ファイルが綴れない名前は綴り直される（`Light Output` は `Light_Output` に、言語の予約語には末尾に `_` が付く）。
- JSON ファイルは `….migrated` に名前が変わり、二度と読まれない。確信できたら削除するか、記録として残す。
- `bdl.toml` は書き直される。

JSON の設計ファイルと `src/` 下の `.bdl` ファイルの両方を持つフォルダは、推測されずに拒否されます。どちらか一方を残してください。JSON 形式に戻る方法はありません。
