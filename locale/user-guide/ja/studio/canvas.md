# キャンバス

キャンバスは設計ページの中央で、設計の構造の絵です。その上のすべてに意味があり、各視覚チャネルはただ 1 つのことを意味します。

## 印の意味

| 見えるもの | 意味 |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ソケットの色** | _どのコンセプトか_——各コンセプトは固有の色相を持ち、現れる場所すべてで同じ |
| **ソケットの形** | コンセプトの _値の形式_：○ 量、◇ オン/オフ、□ 個数。値の形式が _後で決める_ の間は**中空の輪** |
| **概念の色をした、ソケットからソケットへのリンク** | _この式があのブロックを読む_（ブロック → 式のそのブロック用入力ソケット、読まれるブロックの色）、_この式があのブロックを定義する_（マッピングブロックからそのブロックへの短い継ぎ目）、または _このブロックがあの出力を駆動する_（ブロック → シンク） |
| **マッピングブロック上の `?` と書かれた中空のソケット** | 式の空き位置：ブロックをそこへ落とすと埋まる |
| **破線の輪郭** | ドライバかドメインのない出力 |
| **ブロックの左端のバー、入口の矢印、_入力元_ という語** | **入力元**：式のないブロック——その値は環境が提供します。何も欠けていません |
| **数式行の赤い印** | 数式が検査を通らない——_今、間違っている_ のであって、_まだ_ ではない |
| **_競合_、_不正_、_ドメインなし_ という語** | ノードが持ちうる唯一の状態語。その状態が成り立つ間だけ（駆動されなければならない出力はその間 _必須_ と表示され、入力元は _入力元_ と表示される） |
| **ノード右端の小さな名前** | そのタイミングドメイン |
| **アクセントカラー** | 選択——それ以外にはない |

位置、大きさ、リンクの向きに**意味はありません**。読みやすさのためにデータは左から右へ描かれます。リンクは、あるブロックの式が別のブロックの名前を挙げていることを示します。何かの実行順序は示さず、演算子ごとのノードもありません——算術は式フィールドの中にあります。コンセプトとルールはキャンバス上にはまったくありません。それらはテンプレートで、サイドバーにあります。

## ノード

![The Source block tilt with a bar at its left edge, an entry arrow and the word Source in its header, no input socket and one round output socket labelled Tilt; a link from it into the mapping block dimByTilt, with one input socket on the left labelled tilt — the block its formula reads — an output socket on the right and the formula dimByTilt(tilt) on the line below with a chevron at its end; a short link from that output socket into the block brightness, outlined in the accent colour because it is selected, with an input socket on the left, the domain name interaction beside it and one output socket on the right labelled Brightness; the light sink at the right with the word required in its header, a single input socket and a bar at its right edge; tilt and the output carry the domain name interaction too.](../../../../docs/user-guide/assets/studio/node-anatomy.png)

_チルトランプのノード構造：入力元 tilt、読み取りソケットと式を持つマッピングブロック dimByTilt、それが定義するブロック brightness（選択中）、そしてシンク light。_

キャンバスが描くのは**ブロック**——[用語集](../../../../docs/user-guide/reference/terminology.md)でいう _Sem ブロック_——で、設計の値ごとに一つです。ブロックは何も読まない関係——概念の一つの値で、ティックごとに一度更新されます。小さな箱です。名前と、該当するときだけ一つの状態語を持つヘッダー、右側に概念の色と形の出力ソケットを一つ持ち概念名の書かれた行、ブロックにタイミングドメインがあればその名が行の左に。式を持つブロックは、その式を独立したノード、すなわち**マッピングブロック**として隣に持ちます。ヘッダーには式が適用する規則の名（上の図では _dimByTilt_）、規則を適用しないときは _Formula_ の語。左には**式が読むブロックごとに**入力ソケットが一つずつあり、そのブロックの名が書かれます。右には出力ソケットがあり、短いリンクで定義するブロックへつながります——式はブロックの唯一の定義であり、この継ぎ目が引き直されることはありません。その下の行が式です。マッピングブロックは現れたときブロックの左に置かれ、それ以後は独立したノードです——どちらをドラッグしても、動くのはそれだけです。式の行の端に小さな山形があり、クリックする（またはメニューの **Show Formula**）とマッピングブロックが展開し、[式エディタ](formula-editor.md)と同じ描き方——分数、分岐、単位——で式を示し、その下に最初の指摘と、インスペクタを開く **Edit formula** が出ます。展開された式は読むためのもので、クリックするとブロックが選択され、何も変わりません。どの式が展開されているかはプロジェクトに保存されません。マッピングブロックをクリックするとそのブロックが選択されます。一つの宣言、二つのノード、一つのインスペクタです。

![The mapping block dimByTilt with its read socket tilt, its formula line dimByTilt(tilt) and a downward chevron, extended below by a region showing dimByTilt applied to tilt and the link Edit formula; to its right, joined by a short link, the block brightness with its socket labelled Brightness.](../../../../docs/user-guide/assets/studio/formula-unfolded.png)

_brightness のマッピングブロックを展開したところ：式の行の山形が下向きになり、保存された式 dimByTilt(tilt) がその中に描かれ、下に Edit formula がある。右にはそれが定義するブロック brightness。_

**コンセプト**はブロックの元になるテンプレートです。名前、値の形、色を持ちます。ノードではなく、サイドバーにあり、そのすべてのブロックが出力ソケットにその色を付けています。製品には、そのような値がある数だけ同じコンセプトのブロックがあってよく（`sensorA`、`sensorB`、`roomTemperature`、すべて _Temperature_）、それを数えるものはありません。**ルール**——あるコンセプトを読み取り別のコンセプトを生成する関係、ランプの `dimByTilt`——もテンプレートです。ブロックの式の中で、生成するブロックの数だけ適用され、キャンバスではなくサイドバーに自分のインスペクタとともに置かれます。適用するブロックは式の中でその名前を挙げ（`dimByTilt(tilt)`）、そのインスペクタは _適用する規則_ の下にそれを列挙します。

式が**読む**各ブロックは、読まれるブロックの出力ソケットからマッピングブロックのそのブロック用入力ソケットへ、読まれるブロックの色のリンクでマッピングブロックにつながれます。これらのリンクは設計の依存関係で、式に対するコンパイラの解析から読み取られ、解析が届いたときに現れます。一本を変えるには式を変えます——ブロックをマッピングブロックの上に落とす（下記）か、リンクを **Disconnect** します。コンパイラが式の中の名を空き位置 `?` に置き換え、マッピングブロックはそれを中空のソケットとして示します。

**入力元**は式のないブロックです——上の `tilt`：環境がその値をアクティベーションごとに提供します。ヘッダーに _入力元_ という語、名前の前に入口の矢印、**左**端にバー（環境側。設計内の何もそれに値を送りません）、出力ソケット 1 つ、入力ソケットなしで描かれます。破線ではありません。何も欠けていません。実際の製品で値を提供するもの——センサー、ボタン、アナログ線——はデプロイの事柄で、キャンバス上の印ではありません。入力元に式を与えれば、設計の中で計算される値になります。

**物理出力**はシンクです。名前と右側の語を持つ色付きのヘッダー——設計が完成する前に駆動しなければならない出力には _必須_、あるいはそれを上書きする状態（_ドメインなし_、_競合_、_不正_）。受け取るコンセプト名付きの入力ソケット 1 つ。右端にタイミングドメイン。右側に縦のバー——そこから何も流れ出ません。

選択されたノード（上の `brightness`）はアクセントカラーで縁取られます。キャンバス上でこの色を使うものは他にありません。

コンポーネントを組み合わせるプロジェクトには、**インスタンスノード**（ポートごとに 1 行、本体にコンポーネント名）と、**振る舞い領域**または折りたたまれた**振る舞いボックス**も表示されます。[システムプロジェクト](../../../../docs/user-guide/studio/system-projects.md) を参照。

どのノードにも置き場所があります。一度もレイアウトされていないプロジェクト——手書きのもの、テンプレート、デモ——は**自動配置**された状態で開きます。ブロックはそれが読み取るブロックの後に、左から右へ列をなし、重なりません。この配置はプロジェクトのレイアウトとして保存されます。レイアウトのあるプロジェクトで自分が置いていないブロック——コードビューやコードエディタで作ったもの——は、読み取るものの隣、既にあるものの下に置かれます。自分で置いたものは動きません。好きな場所へドラッグしてください（[デザイン、コード、分割](code-view.md)）。設計全体を配置し直すには、キャンバスのメニューから**自動配置**を選びます。**自動配置を元に戻す**は、次に動かすまでの間、元のレイアウトに戻します。配置が変えるのはレイアウトだけで、設計は変わりません。

## 選択する

キャンバスはデスクトップ CAD ツールと同じやり方で選択します。

| 操作 | 結果 |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ノードをクリック | それだけを選択する（インスペクターが追従）。すでに選択に含まれるノードをクリックすると選択は保たれ、そのノードがアクティブになる |
| リンクをクリック | 選択します。インスペクタが両端とリンクの意味を示します（_brightness が light を駆動する_、_brightness が tilt を読み取る_）。バインディングも同じように選択されます |
| 空のキャンバスをクリック | 選択を解除する |
| ⌘-クリック（Windows と Linux では Ctrl-クリック） | ノードを選択に加える。すでに含まれていれば外す |
| ⇧-クリック | アクティブなノードからこのノードまでの接続の連鎖を選択する——それがちょうど 1 本あるとき。そうでなければこのノードだけが加わる |
| 空のキャンバスで**左から右へ**ドラッグ | **ウィンドウ**：矩形に完全に含まれるノードがすべて選択される（実線の枠） |
| 空のキャンバスで**右から左へ**ドラッグ | **交差**：矩形に含まれる、_または触れた_ ノードがすべて選択される（破線の枠）。上下の向きは関係ない |
| ⌘-ドラッグ / ⇧-ドラッグで矩形 | 矩形内のノードを選択に加える / から外す（ポインターの横に `+` または `−`）。離す前にノードが結果を示す |
| ⌘A | 表示中のすべてのノードを選択 |
| Esc | 進行中のもの——矩形、移動、リンク——をキャンセルする。何も進行していなければ選択を解除する |

選択されたノードはアクセントカラーで縁取られます。複数を選択したとき、_アクティブ_ なノード——最後にクリックしたもの、インスペクタが最初に表示するもの——にはもう一つの輪が付きます。ポインタの下にあるリンクには柔らかな光と手のカーソルが現れ、選択されたリンクはアクセントカラーで描かれ、両端に輪が付きます。プロジェクトサイドバーの選択も同じです。クリックで 1 行、⌘-クリックで追加や除外、⇧-クリックでアクティブな行からその行までのすべてを選びます。

**クイックアクション。** 選択したオブジェクト——リンク、ブロック、ビヘイビア——にポインタを合わせると、その横に小さなアイコンの列が現れます。**⋯** は右クリックと同じメニューを開き、その隣にオブジェクト固有の操作——切断できるリンクには **× 切断**、ブロックには **× 削除**、ビヘイビアには**折りたたむ** / **展開**——が並びます。アイコンに重ねると名前が表示されます。オブジェクトからアイコンへ移動する間、列は表示されたままで、離れたとき、選択を変えたとき、メニューを開いたときに消えます。マウスは必須ではありません。⌫ / Delete は選択したリンクを切断し、メニューキー（または ⇧F10）は選択したオブジェクトのメニューを開きます。

## 移動と表示

| 操作 | 結果 |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 選択中のノードをドラッグ | 選択全体が間隔を保ったまま一緒に動く。離すと位置が保存される（設計の変更ではない） |
| 選択されていないノードをドラッグ | それが選択になり、動く |
| 振る舞いのタイトルバンドをドラッグ | その関係が動く |
| ← → ↑ ↓ | 選択をグリッド 1 段だけ動かす。⇧ で 1 ポイント |
| 中ボタンドラッグ、Space + ドラッグ、トラックパッドの 2 本指 | パン |
| スクロールホイール、ピンチ、⌘ + 2 本指 | ポインタを中心にズーム |
| Home または ⌘0 | 設計全体を表示 |

## 接続する

| 操作 | 結果 |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ブロックの出力ソケットを式のないブロックの上へドラッグ | そのブロックの式がその名になる（`= tilt`）：式のテキスト編集で、コンパイラが検査する。隣にマッピングブロックが現れる |
| ブロックの出力ソケットを中空の `?` ソケットの上、または `?` ソケットのあるマッピングブロックの上へドラッグ | 式のその空き位置をブロックの名前で埋めます（コンパイラが配置します）。ドラッグ中はすべての空き位置に光の輪が表示されます |
| ブロックの出力ソケットを、そのコンセプトを受け入れる**出力**の上へドラッグ | それを出力のドライバにします。ドラッグ中、受け入れられるソケットには光の輪が、互換性のないソケットには禁止カーソルが表示されます |
| 駆動されている出力のソケットからドラッグして離し、空のキャンバスで放す | ドライバを切断します——**×**、リンクのメニューの**切断**、インスペクタのボタン、選択したリンクでの ⌫ と同じです |
| マッピングブロックの入力ソケットから引き離し、空のキャンバスで離す | 読み取りリンクも同じ：式の中の名が空き位置 `?` になる（コンパイラが編集する） |
| ドラッグ中のリンクを空のキャンバスに落とす | 何も起きない（ノードは作られない） |
| ⌫ / Delete | 選択を削除する——複数のオブジェクトを一度に。そのうちの 1 つが選択の外からまだ使われていれば何も削除されず、バナーが理由を述べる |
| ブロックまたはそのマッピングブロックをダブルクリック | そのブロックをその場で名前変更（出力はインスペクタで名前変更、インスタンスはそのソースを開く） |
| 右クリック、または Control-クリック | コンテキストメニュー（下記） |
| ライブラリタブの行をキャンバスへドラッグ | そのカテゴリのコンセプトシートを開きます。名前を付けたコンセプトは、そのブロックとともにドロップした位置に作られます |
| プロジェクトサイドバーの概念の行をキャンバスへドラッグ | その概念のブロックシートを開く：ブロックに名前を付けると、落とした位置に置かれる |

**出力を駆動する。** 出力は、出力のタイミングドメインで、出力が受け入れるものをちょうど生成するブロックによって駆動されます——自分の値を持たないルールによってではありません。ブロックの出力ソケットを出力の上へドラッグするか、出力を選択してそのインスペクタの _接続_ ポップアップでブロックを選びます。ポップアップは条件を満たすブロックを列挙します。キャンバス上のエッジは駆動するブロックから伸び、出力のコンテキストメニューがその名前を示します（_ドライバを表示: brightness_）。

## コンテキストメニュー

メニューは右クリックしたものについてだけです。開いている間、キャンバスは待ちます。メニューの後ろでは何も動かず、スクロールせず、光りません。外側での最初のクリックはメニューを閉じるだけで、他には何もしません。別の場所で右クリックすればそこへ移ります。↑ ↓ ⏎ と Esc は他のメニューと同じです。

**空のキャンバス**の上で：**Add Block ▸**——_of Tilt_、_of Brightness_……設計の概念ごとに一項目で、それぞれその概念の**ブロックシート**を開きます。ブロックに名前を付け——製品でそれが何であるか（`lidTilt`、`roomTemp`）——クリックした位置に置かれます。式を与えるまでは入力元です。プロジェクトサイドバーの概念の行をキャンバスへドラッグしても、落とした位置に同じシートが開きます。続いて **New Concept ▸**——_Recent_、四種の値（_On / off_、_Count_、_Level_、_Decide later_）、_Quantities ▸_（_Angle_、_Length_……）、_More…_（Library タブを開く）で、それぞれ[概念シート](../../../../docs/user-guide/studio/library.md#creating-a-concept)を開き、そこで概念に名前を付けると、概念はそのブロック一つとともにその位置に作られます。**Add Source ▸**——_New source…_ は[入力元シート](../../../../docs/user-guide/studio/library.md#sources)を開き、入力元が提供する概念——既存のもの、または一緒に作る新しいもの——を選びます。**Add Instance ▸** _コンポーネント_ と **New Behavior Group**、続いて **Select All** と **Frame All**、そして **Arrange Automatically** と **Undo Arrange**（[ノード](#the-nodes)参照）。

**ブロック**またはその**マッピングブロック**の上で（同じ一つのメニュー：両者は一つの宣言）：**Edit Definition**（入力元にはない——値は環境が与える）、**Show Formula** / **Hide Formula**（式があるとき）、**Rename**、**Reveal in Code**（Split ビューがその宣言の位置で開く）、**Fix ▸**——コンパイラがそれに提示する修正で、インスペクタの Fixes 節と同じ：準備済みの修正は実行され、選択が必要なものは選択肢を列挙し、言語がまだ表現できないものは理由付きで灰色表示。続いて **Group as Behavior**、**Add to Group ▸** または **Remove from …**、そして **Delete _名前_**。

**出力**の上で：**Show Driver: _名前_**、**Rename**、**Reveal in Code**、**Fix ▸**（値を接続、駆動元を切断）、**Delete _名前_**。**リンク**の上で：**Show _一端_**、**Show _他端_**、**Disconnect**（コンポーネント間のバインディングでは **Show Binding** も）。右クリックはノードと同様、まずリンクを選択します。**Disconnect** は設計がその一本を失えるところでだけ提示されます：出力の駆動元、バインディング、読み取りリンク（式の中の名が `?` になる）。マッピングブロックからそのブロックへの短い継ぎ目は式そのものなので項目がありません——インスペクタの _Detach definition_ が式全体を取り去ります。**インスタンス**の上で：**Edit Source**、**Rename**、**Reveal in Code**、**Delete _名前_**。**振る舞い**の上で：**Rename**、**Collapse** / **Expand**、**Package as Reusable Component…**、**Ungroup**。概念にはノードがありません。そのメニューはサイドバーにあります。

**複数の選択ノード**の 1 つで：メニューはそれら全体についてです——**振る舞いとしてグループ化（_n_ 個の関係）**と **_n_ 個のオブジェクトを削除**。

## キャンバスが決して示さないもの

下書きの式（入力したが追加していない式はキャンバス上の何も変えません——そのリンクも。ステータス行が数えます）、値（シミュレーションページにあります）、関係が自分の前回の値を記憶すること（`delay` はリンクを描きません）、識別子や型名（説明にあります）。
