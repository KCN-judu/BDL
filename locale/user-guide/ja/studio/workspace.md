# ワークスペース

Studio には 2 つの画面があります。**プロジェクトマネージャー**（プロジェクトを開いていない）と**ワークスペース**（プロジェクトを開いている）です。ワークスペースは 1 つのウィンドウで、下部にワークフロー順にページが並びます。

![The Studio window at 1440 by 900: the toolbar with the project name tilt-lamp, undo, redo, Save and Close; the Project sidebar on the left listing Concepts, Mappings, Timing domains, Outputs, Contexts and Components; the canvas in the middle with the tilt lamp's nodes; the inspector on the right showing the selected relationship brightness with its Meaning, Reads, Produces, Relationship, Timing and Drives sections; the status line reading Saved, 2 concepts, 3 mappings, 1 not yet defined, Compiler 0.1.0; and the page bar with Design, Simulate, Deploy and Monitor.](../../../../docs/user-guide/assets/studio/workspace.png)

_傾きランプを開き brightness を選択したワークスペース：ツールバー、サイドバー、キャンバス、インスペクター、ステータス行、ページバー。_

## 領域

**ツールバー**——プロジェクト名（未保存の変更がある間は _編集済み_ が続く）、取り消しとやり直し、保存（編集中のみ有効）、閉じる。

**サイドバー**（左）——設計ページでは 2 つのタブ。**プロジェクト**はプロジェクトのオブジェクトを種類別に（_コンセプト_、_マッピング_、_タイミングドメイン_、_出力_、_コンポーネント_、_インスタンス_、_振る舞い_）、それぞれ作成用の **+** 付きで並べます——_コンテキスト_ の見出しは空のままです（コンテキストはまだツールの一部ではありません）。**ライブラリ**は既製のコンセプトテンプレートです。[ライブラリ](../../../../docs/user-guide/studio/library.md) を参照。シミュレートページとデプロイページは独自のコントロールをここに置きます。

**ページ内容**（中央）——設計ではキャンバス、シミュレートではトレース、デプロイでは判定。

**インスペクター**（右）——選択中のオブジェクト：その意味、変更できること、変更が影響するもの。[インスペクター](inspector.md) を参照。

**ステータス行**——文書の状態（_保存済み_ / _編集済み_）、次に件数とまだ決まっていないもの（_未定義 1 件_、_出力が未完了_、_瞬時サイクルあり_、_ドメインをまたぐ読み取り_、_未追加の定義 N 件_）、次にコンパイラ接続。拒否された操作のエラーはページ内容の上に _閉じる_ リンク付きの**バナー**として現れます——ダイアログにはなりません。

**ページバー**——使う順に並んだページ：

| ページ | 答える問い | ショートカット |
| ------------ | --------------------------------------------------------------------------------------------- | -------- |
| **設計** | 製品は何をするか | ⌘1 |
| **シミュレート** | 時間とともに何をするか | ⌘2 |
| **デプロイ** | このボードに収まるか | ⌘3 |
| **モニター** | 今何をしているか——_未実装_。ページにはライブ値はテレメトリとともに提供されるとある | ⌘4 |

ページバー左端のボタン（⊞）はプロジェクトを閉じてプロジェクトマネージャーに戻ります。右端の歯車は**環境設定…**を開きます。Studio の表示言語（システムのデフォルト、English、简体中文、日本語）で、Studio の表示だけを変え、BDL のソース、プロジェクトファイル、コンパイラは決して変えません。同じリンクはプロジェクトマネージャーにもあります。

## 保存、取り消し、リビジョン

**⌘S** または**保存**はプロジェクト全体をそのフォルダに書き込みます——設計、レイアウト、そして未完了の編集すべて：入力したが追加していない数式、まだビルドできないコードビューのテキスト。設計の変更はプロジェクトの新しい _リビジョン_ として記録され、**⌘Z** / **⇧⌘Z** でそれらを行き来します。ノードの移動、パネルのサイズ変更、グループの折りたたみは設計の変更ではありません。保存はされますがリビジョンは作りません。入力したが追加していない数式は _下書き_ です——選択やページを切り替えても保持され、プロジェクトとともに保存され、追加するか元に戻すまでステータス行は _未追加の定義_ として数えます。

## プロジェクトを閉じる

**閉じる**、プロジェクトマネージャーボタン（⊞）、**⌘W**、**⌘Q**、メニューの終了、ウィンドウの閉じるボタン、別のプロジェクトを開く・作成する、これらはすべて、プロジェクトが保存済みの内容と異なるとき同じ質問をします：

> 「lamp」への変更を保存しますか？ **保存しない** · **キャンセル** · **保存**

**保存**は今の状態をすべて保存してから閉じます。保存が拒否された場合（ファイルがディスク上で変更された——バナーを参照）、プロジェクトは開いたままです。**保存しない**は閉じます。次に開くと最後に保存した状態に戻ります。**キャンセル**（Esc）は何も変えません。_保存済み_ のプロジェクトはすぐに閉じます。二度は尋ねず、質問が開いている間は何も閉じません。

## 情報の 3 つのレベル

Studio は設計を 3 つのレベルで示し、それらを分けて保ちます：

1. **キャンバス**——目に見える構造：形、色、リンク、破線の輪郭、赤い印。型名も識別子もありません。
2. **インスペクター**——設計者の語彙：_意味_、_値_、_読み取り_、_生成_、_更新ドメイン_、_駆動先_。検出項目は製品の言葉で、関係するフィールドの横に。
3. **説明**——すべてのインスペクターの末尾にある折りたたまれた開示部：識別番号、形式的なインターフェースと項、診断コード、リビジョン。最初の 2 つのレベルの何もこれに依存しません。

このガイドも同じ順序に従います。キャンバスとインスペクターを説明し、残りは _説明_ と技術文書を指し示します。
